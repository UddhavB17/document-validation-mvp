# Steps

## 1. Sweep

Run and fix every hit, file by file, committing per file:

```bash
rg -n "INSERT OR IGNORE|INSERT OR REPLACE|PRAGMA|sqlite_master|lastrowid|AUTOINCREMENT|datetime\('now'\)|date\('now'\)|strftime\(|GROUP_CONCAT|julianday|\bIFNULL\b|\|\|" --type py -g '!tests/**' -g '!alembic/**'
rg -n "= 1\b|= 0\b" --type py routes services database | rg -i "bool|is_|active|enabled|escalated|reused"   # int-as-bool suspects
rg -n "json_extract|->>" --type py
```

Replacements (contracts §1): `ON CONFLICT`, `RETURNING id`, Python-side
timestamps, `COALESCE`, `STRING_AGG`/Python-side join, `True/False` params.
`||` string concat works in both; leave it. For `GROUP_CONCAT` prefer fetching
rows and joining in Python.

Type traps to check: columns declared `TEXT` that receive Python `dict` (must be
`json.dumps`), `INTEGER` receiving `bool` (fine in PG only if declared BOOLEAN —
check the declaration), `REAL` vs `NUMERIC`, empty-string vs NULL comparisons
(`WHERE col = ''` vs `IS NULL`), `LIMIT ? OFFSET ?` (fine), `LIKE` case
sensitivity (PG is case-sensitive; use `ILIKE` where the SQLite code relied on
case-insensitive `LIKE` — grep `LIKE`).

## 2. Postgres test fixture (`tests/conftest.py`)

When `DATABASE_URL` is set: at session start run `alembic upgrade head` against
it; before each test truncate all tables (`TRUNCATE ... RESTART IDENTITY CASCADE`
over the table list from `information_schema`). When unset, keep the current
SQLite temp-file behaviour untouched.

## 3. Alembic baseline (`alembic/versions/0001_baseline.py`)

Translate the final `SCHEMA_STATEMENTS` + all registered schema modules into one
migration using `op.execute()` with PostgreSQL DDL (`BIGINT GENERATED BY DEFAULT
AS IDENTITY`, `BOOLEAN`, `TIMESTAMPTZ` only for new columns where ws-a used ISO
text — keep `TEXT` for anything the code compares as strings; consistency with
the code beats purity). Include every index. `downgrade()` drops everything.
Add `tests/test_schema_parity.py`: table and column names from `alembic upgrade
head` on Postgres equal those from `init_db()` on SQLite (compare sets; ignore
types).

`init_db()` on Postgres stays a connectivity check; document that schema comes
from `alembic upgrade head` (run as a release step, see ws-j).

## 4. Run the suite on Postgres until green

```bash
docker compose -f docker-compose.dev.yml up -d
DATABASE_URL=postgresql://dmef:dmef@localhost:5432/dmef python -m pytest -q -x
```

Iterate. Typical failures: ordering without `ORDER BY` (add it), `fetchone()`
on `INSERT` without `RETURNING`, transactions left open by tests, `sqlite3.Row`
assumptions (`row[0]` positional — the wrapper supports it? if not, switch to
`row["col"]`), tests that open `sqlite3.connect(DATABASE_PATH)` directly (rewrite
to `get_connection()`).

## 5. CI and docs

- `ci.yml`: remove `continue-on-error` from `tests-postgres`; both jobs required.
- `docs/DEPLOY_NEON.md`: create project → copy pooled connection string →
  `DATABASE_URL=...?sslmode=require` → `alembic upgrade head` → bootstrap admin
  env → verify with `/health`. Note pooled vs direct endpoints (alembic needs
  direct), `pool_pre_ping`, and Neon autosuspend behaviour with a 2 s worker poll
  (recommend `poll_seconds=5` in production and note the cold-start latency).
- `/health` `database` key already exists (ws-h); make sure it reports the
  dialect: `"database": {"status": "ok", "dialect": "postgresql"}`. If the
  shape change breaks a frontend schema, keep `"database": "ok"` and add
  `"database_dialect"` instead.
