# Shared contracts for all workstream agents

Every workstream agent (`.opencode/agents/ws-*.md`) codes against this file.
If you need to change a contract, stop, add a `NEEDS-COORDINATION` section to
your PR description explaining why, and continue with the parts of your work
that do not depend on the change. Do not silently diverge.

Repository: DMEF (Document Matching Early Finder). FastAPI backend at the repo
root (`main.py`, `routes/`, `services/`, `database/`), Next.js 14 frontend in
`frontend/`. Python 3.11 only. Tests: `python -m pytest -q`.

---

## 1. Database access (`database/db.py`)

`get_connection()` keeps its current name and shape:

```python
from database.db import get_connection

with get_connection() as connection:
    row = connection.execute(
        "SELECT id, status FROM applications WHERE id = ?", (application_id,)
    ).fetchone()
    row["status"]            # rows support string-key access
    connection.execute("UPDATE applications SET status = ? WHERE id = ?", ("x", 1))
```

Guarantees provided by the wrapper (owned by `ws-b-storage-db`):

- `?` positional placeholders are accepted and translated to the active
  dialect (`?` for SQLite, `%s` for PostgreSQL). A literal `%` in SQL must be
  written as `%%`.
- `.execute()` returns a cursor-like object with `.fetchone()`, `.fetchall()`,
  `.rowcount`.
- Rows support `row["column"]`, `dict(row)`, and `row.keys()`.
- The context manager commits on success and rolls back on exception.
- Dialect is selected by `DATABASE_URL`. No value → SQLite at `DATABASE_PATH`
  (default `data/dmef.db`). Tests keep using SQLite through the same wrapper.

Rules for all SQL written or touched in this phase (dialect neutral):

| Do not write | Write instead |
|---|---|
| `INSERT OR IGNORE` | `INSERT ... ON CONFLICT (...) DO NOTHING` |
| `INSERT OR REPLACE` | `INSERT ... ON CONFLICT (...) DO UPDATE SET ...` |
| `cursor.lastrowid` | `INSERT ... RETURNING id` then `.fetchone()["id"]` |
| `PRAGMA ...`, `sqlite_master` | nothing; the wrapper owns connection setup |
| `date(col) = date('now')` | `col >= ? AND col < ?` with ISO bounds from Python |
| `datetime('now')` | pass `datetime.now(UTC).isoformat()` from Python |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `INTEGER PRIMARY KEY` (SQLite) / `BIGINT GENERATED BY DEFAULT AS IDENTITY` (Postgres) — schema is dialect-specific and lives in `database/models.py` (SQLite) and `alembic/` (Postgres) |
| `0` / `1` for BOOLEAN columns | Python `True` / `False` |

JSON payload columns are `TEXT` containing `json.dumps(...)`. No JSONB in this
phase. Do not query inside JSON in SQL.

## 2. Object storage (`services/storage/__init__.py`)

```python
from typing import Protocol, BinaryIO

class ObjectStore(Protocol):
    def put(self, key: str, data: bytes | BinaryIO, content_type: str) -> str: ...
    def get(self, key: str) -> bytes: ...
    def open(self, key: str) -> BinaryIO: ...          # streaming read
    def exists(self, key: str) -> bool: ...
    def delete(self, key: str) -> None: ...
    def signed_url(self, key: str, expires_seconds: int = 600) -> str: ...
    def list(self, prefix: str) -> list[str]: ...

def get_store() -> ObjectStore: ...   # DMEF_STORAGE_BACKEND=local|gcs
```

- `LocalObjectStore` writes under `DMEF_LOCAL_STORE_DIR` (default
  `data/store`) and `signed_url` returns `/storage/{key}` served by a small
  authenticated route (admin or the owning request only).
- `GcsObjectStore` uses `DMEF_GCS_BUCKET` and Application Default Credentials.
- Keys (always relative, never absolute paths):

```text
applications/{application_id}/source/{original_filename}
applications/{application_id}/manifest.json           # raw trusted dump/manifest
applications/{application_id}/ocr-export.json         # generated on demand
applications/{application_id}/reports/{name}.json
jobs/{job_id}/...                                      # temp only, deleted on completion
```

- No rendered page images and no per-page OCR JSON are stored durably.
  Evidence pages are rendered on demand from the source PDF.
- Working directory for a running job: `DMEF_JOB_WORK_DIR/{job_id}` (default
  `/tmp/dmef-jobs`). Always deleted in a `finally`.
- Database columns store the **key**, in `*_key` columns
  (`uploaded_files.storage_key`, `intake_packages.source_zip_key`,
  `intake_packages.normalized_pdf_key`). Legacy `file_path` columns stay
  readable for the archive but are never written by new code.

## 3. Schema registry (`database/schema_registry.py`)

```python
SCHEMA_SOURCES: list[list[str]] = []   # each item is a list of CREATE TABLE/INDEX statements (SQLite dialect)

def register(statements: list[str]) -> None: ...
def all_statements() -> list[str]: ...
```

`database/db.py.init_db()` executes `database.models.SCHEMA_STATEMENTS` then
`all_statements()`. Streams that add tables (auth, llm_calls) put them in their
own module and call `register(...)` at import time from `database/__init__.py`
(one import line each). `init_db()` is called once at startup and in tests,
never inside request handlers.

## 4. Job table contract (`pipeline_jobs`)

Existing columns stay. Added columns (SQLite schema added by `ws-a-data-diet`,
used by `ws-c-queue-batch`):

```text
max_attempts   INTEGER NOT NULL DEFAULT 3
next_run_at    TEXT            -- ISO UTC; NULL means now
failure_reason TEXT            -- human-readable, shown to operations after final failure
batch_id       TEXT            -- groups files uploaded together
```

Status values: `queued | running | retrying | completed | failed | paused |
cancelled | stale`. `retrying` = failed with `attempt < max_attempts` and
`next_run_at` set. `failed` = attempts exhausted; `failure_reason` mandatory.

Worker dequeue (one job at a time, one worker replica):

```sql
-- PostgreSQL
SELECT id FROM pipeline_jobs
WHERE status IN ('queued','retrying') AND (next_run_at IS NULL OR next_run_at <= ?)
ORDER BY id LIMIT 1 FOR UPDATE SKIP LOCKED;
-- SQLite: same query without FOR UPDATE, inside BEGIN IMMEDIATE
```

Backoff between attempts: 30 s, 120 s (two retries after the first failure).

## 5. Operations payload (`GET /ops/applications/{id}`)

```json
{
  "application_id": 12,
  "loan_id": "LN-001",
  "applicant_name": "…",
  "status": "needs_review | clean | processing | failed",
  "processing": {"stage": "…", "percentage": 0, "attempt": 1, "failure_reason": null},
  "summary": {"en": "…", "hi": "…"},
  "top_findings": [
    {
      "code": "NAME_MISMATCH",
      "severity": "HIGH | MEDIUM | LOW",
      "title": {"en": "…", "hi": "…"},
      "detail": {"en": "…", "hi": "…"},
      "pages": [3, 4],
      "evidence": {"page": 3, "bbox": [0.12, 0.40, 0.55, 0.44], "text": "…"}
    }
  ],
  "pages_to_verify": [{"page": 7, "document": {"en": "Bank statement", "hi": "…"}, "problem": {"en": "…", "hi": "…"}}],
  "checklist": {"total": 44, "found": 30, "missing": 4, "not_checked": 10,
                "rows": [{"s_no": 1, "description": "…", "status": "FOUND | MISSING | NOT_CHECKED", "pages": [1, 2]}]}
}
```

- `top_findings` has at most 5 items, ordered by severity then category order.
- `code` is one of the nine finding codes in section 11.
- No `rule_id`, no OCR text, no JSON dumps, no internal stage names in this
  payload. Everything a non-technical user sees comes from this endpoint.
- `bbox` is normalized `[x0, y0, x1, y1]` in 0–1 page coordinates; may be null.

## 6. Authentication and roles

- Tables `users(id, email UNIQUE, display_name, role, is_active, created_at, created_by)`
  and `user_passwords(user_id PK, password_hash, updated_at)`. Roles:
  `admin`, `user`. Hash with bcrypt.
- `services/auth/dependencies.py` exports `get_current_user` and
  `require_role(*roles)` FastAPI dependencies. Bearer JWT (`DMEF_AUTH_SECRET`,
  HS256, 12 h expiry) in `Authorization: Bearer …`.
- `/health` and `/auth/login` are the only unauthenticated routes.
- Admin-only: `/settings*`, `/admin/*`, `/review/applications/{id}/ocr-json`,
  `/review/applications/{id}/pages/{n}/text`, job control
  (pause/cancel/resume/restart), `/upload/*`.
  Operations: `/ops/*`, `/review/worklist`, `/review/applications/{id}/status`,
  `/review/applications/{id}/source-page/{n}`, `/decision*`.
- Frontend: `frontend/middleware.ts` redirects unauthenticated users to
  `/login`; token stored in an httpOnly cookie set by a Next route handler
  (`frontend/app/api/session/route.ts`); role read from the JWT payload.
- Bootstrap: on empty `users`, `DMEF_BOOTSTRAP_ADMIN_EMAIL` +
  `DMEF_BOOTSTRAP_ADMIN_PASSWORD` create the first admin.

## 9. File ownership and shared-append files

Each brief lists the files it owns. You may create new files inside your
owned directories. You must not edit files owned by another stream. If a change
is unavoidable, make the smallest possible edit and document it under
`NEEDS-COORDINATION` in the PR.

Shared-append files: only add lines, never reorder or reformat:

- `main.py` (router registration, one `include_router` line per stream)
- `requirements.txt`
- `.env.example`
- `frontend/lib/api.ts` (append your schemas at the bottom under a

## 11. Finding codes (operations vocabulary)

Order is priority order. `ws-f-accuracy-ops-api` owns the mapping from
rule IDs and the EN/HI templates; `ws-e-ops-ui` renders them.

| Code | Source rule families | EN title (template) |
|---|---|---|
| `NAME_MISMATCH` | `APPLICANT_NAME_MISMATCH`, `TRUSTED_*NAME*_MISMATCH`, `CROSS_DOCUMENT_APPLICANT_NAME_MISMATCH`, `NAME_MISMATCH`, `APPLICATION_NAME_MISMATCH` | Applicant name does not match |
| `ID_MISMATCH` | `PAN_NUMBER_MISMATCH`, `AADHAAR_NUMBER_MISMATCH`, `TRUSTED_PAN_*`, `TRUSTED_AADHAAR_*`, `DATE_OF_BIRTH_MISMATCH`, `INVALID_PAN_FORMAT` | PAN / Aadhaar does not match |
| `ADDRESS_MISMATCH` | `TRUSTED_*ADDRESS*_MISMATCH`, `CROSS_DOCUMENT_ADDRESS_MISMATCH`, `AADHAAR_ADDRESS_MISMATCH`, `ADDRESS_MISMATCH` | Address does not match |
| `MISSING_DOCUMENT` | `MISSING_DOC_S*` | Required document not found |
| `BANK_STATEMENT_OLD` | `PERIOD_*`, `DATE_CHECK_S*` | Bank statement older than three months |
| `PAGE_UNREADABLE` | `UNREADABLE_PAGE`, `DOCUMENT_NOT_READABLE` | Page too blurry to read |
| `OCR_FAILED` | `LOW_OCR_CONFIDENCE*`, `LOW_CONFIDENCE_PAGE`, `OCR_BUDGET_PARTIAL_SCAN` | Could not read this page reliably |
| `DATA_MISSING` | `*_NOT_FOUND`, `*_EXTRACTION_UNRELIABLE`, `FIELD_VALUE_MISSING_S*` | Expected information missing |
| `PROCESSING_ERROR` | `PAGE_PROCESSING_ERROR`, job `failure_reason` | File could not be processed |

Anything not in these families (unclassified pages, ownership heuristics,
low-confidence classification) is admin-only and never appears in the
operations payload.
